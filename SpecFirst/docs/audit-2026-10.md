# October 2026 audit corrections

The current main confirms that CI sanitizer and warnings-as-errors options are
unused and desktop HTTP is built without TLS. Implement target-scoped build
controls, require verified TLS by default, and validate native builds and tests.
Third-party code must not inherit the project's warnings-as-errors policy.

Measured AQM facts are an additive chat context feature. Copy the current engine
counters into each new request, identify them as simulation observations, and
omit them when the caller supplies no measurements. Preserve the copied snapshot
on retries. Test measured values, absence, and retry stability.

Investigate the TCP benchmark from actual process output before changing model
semantics. Benchmark failures must retain diagnostics and return nonzero.

The mesh5 failure leaves the client ESTABLISHED and the server SYN_RECEIVED
after losing the final handshake ACK. The handshake timer must keep retrying
the server's SYN-ACK within a finite budget until both endpoints establish.
An established client must acknowledge an exact duplicate SYN-ACK without
resetting sequence numbers or buffers. Exhaustion must close both endpoints,
record SynRetriesExhausted and release listener capacity. Test recovery,
permanent loss, duplicate validation and the unchanged benchmark topology inputs.

Data retry exhaustion must also close both endpoints and record its reason.
Validation must never count a failed session as completed. Headless exit code 2
means all sessions terminated cleanly but at least one exhausted its transport
retry budget; code 1 remains invalid execution/input. Both are nonzero.
The TCP loss benchmark may explicitly accept code 2 as a measured transport
outcome, retaining failed-case counts and metrics. Other errors still fail CI;
other suites remain strict by default. Do not change mesh5's 50% loss or seeds.
